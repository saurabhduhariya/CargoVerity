## 1. Security Architecture & Threat Model

CargoVerity is designed with a defense-in-depth security model to process customs shipping documents while safeguarding sensitive commercial data, protecting credentials, and enforcing strict tenant and role boundaries.

```
+-------------------------------------------------------------------------+
|                              CLIENT BROWSER                              |
|   - Supabase SSR Cookie Session (HTTP-Only, Secure, SameSite=Lax)       |
|   - Rendered PDF Page Images (In-Memory Canvas Only)                     |
|   - Never Receives API Provider Keys or Service Role Secrets            |
+-------------------------------------------------------------------------+
                                    |
                    HTTPS / TLS 1.3 (Bearer JWT)
                                    v
+-------------------------------------------------------------------------+
|                           SERVER API GATEWAY                            |
|   - Server Session & Role Enforcement (Executive vs Manager)            |
|   - Authorization Scoping on All Queries (Owner / Organization Scope)   |
|   - Magic Byte Content Validation (Strict Binary Inspection)             |
|   - Error & Log Sanitization (Zero Stack Traces / Zero PII)             |
+-------------------------------------------------------------------------+
             |                                              |
      Direct TLS Connection                          Short-Lived Signed URL
             v                                              v
+-------------------------+                    +-------------------------+
|     POSTGRESQL DB       |                    |  SUPABASE PRIVATE S3    |
| - Row-Level Integrity   |                    | - Private Bucket        |
| - Foreign Key Cascades  |                    | - Stripped File Names   |
| - Minimum Audit Trail   |                    | - Short TTL (300s)      |
+-------------------------+                    +-------------------------+
```

## 2. Hardening Invariant Checklist (13 Requirements)

### 1. Secrets, Keys, Passwords and Private URLs
- **Repository Scan:** Scanned all git-tracked files with regular expression heuristics (`gsk_`, `sk-or-v1-`, `eyJ`, `postgres://`). Zero production credentials exist in version control.
- **Credential Storage:** All provider keys (`GROQ_API_KEY`, `OPENROUTER_API_KEY`), database connection strings (`DATABASE_URL`, `DIRECT_URL`), and Supabase service keys (`SUPABASE_SECRET_KEY`) reside exclusively in `.env` (server-side only).

### 2. `.env` and Service Credentials Ignored
- **Gitignore Enforcement:** `.gitignore` explicitly ignores `.env` and all `.env.*` variants, exempting only `.env.example`.
- **Template Safety:** `.env.example` contains only blank placeholder keys without default or fallback secrets.

### 3. No Real Personal Data or Client Documents in Fixtures or History
- **Synthetic Documents:** All test fixtures in `sample-docs/` and `public/sample-docs/` are strictly synthetic demonstration documents generated by `scripts/generate-sample-docs.ts`.
- **Watermark Banner:** Every page of every PDF and image carries a prominent security banner:
  `*** SYNTHETIC DEMO DOCUMENT — NOT FOR CUSTOMS FILING ***`
- **Synthetic Entity Registry:** All party names (`Company B (China)`, `Company C (Sweden)`, `Acme Logistics India Pvt Ltd`), addresses, vessel names, and tax IDs are fictional.

### 4. Server-Side Session and Role Enforcement
- **Every Private Route:** Every API route handler under `src/app/api/` invokes `requireAppUser()` or `requireRole()`.
- **Client Trust Zero:** Browser-provided role claims, form bodies, and query parameters are never trusted. Roles are resolved dynamically from the database user record tied to the verified Supabase auth session.
- **Strict Role Separation:**
  - `EXECUTIVE`: Can create shipments, upload documents, trigger extractions, edit fields, resolve checks, and submit shipments. Cannot sign off Manager approvals (`HTTP 403 Forbidden`).
  - `MANAGER`: Can inspect all organizational shipments, audit histories, approve/reject revisions, and export final CSVs.

### 5. Authorization-Scoped Shipment Lookups
- **No ID-Only Lookups:** Direct `findUnique({ where: { id } })` lookups without authorization scoping are prohibited in client-facing routes.
- **Scoped Queries:** All shipment operations use `findFirst({ where: { id, ...(appUser.role === 'MANAGER' ? {} : { createdById: appUser.id }) } })` via `authorizeShipmentAccess()` or `buildShipmentWhere()`. Non-managers cannot view, upload to, or mutate shipments belonging to other executives.

### 6. Private Storage Access & Short-Lived Signed URLs
- **Private Buckets Only:** Supabase Storage bucket (`shipment-documents`) is configured as `public: false`. Public read access is completely disabled.
- **Random Storage Keys:** Storage keys follow the format:
  `shipments/<shipment-uuid>/documents/<document-uuid>/<random-uuid>.<ext>`
  Original customer filenames (e.g. `Client_Secret_Invoice_2026.pdf`) are stripped prior to storage key creation, preventing filename-based information disclosure or directory traversal attacks.
- **Short-Lived Signed Capabilities:** Access to stored files requires an authenticated API call (`GET /api/documents/[id]`) which returns a signed URL with a strictly bounded TTL (`DEFAULT_SIGNED_DOWNLOAD_URL_TTL_SECONDS = 300` seconds / 5 minutes).
- **Zero URL Logging:** Signed URLs are treated as bearer tokens and are never logged to console or telemetry.

### 7. Upload Validation & Binary Magic Bytes
- **No Trust for Content-Type:** The browser-provided `Content-Type` header is ignored during verification.
- **Magic Bytes Validation:**
  - PDF: Verified binary magic bytes `%PDF-` (`0x25 0x50 0x44 0x46 0x2D`).
  - PNG: Verified binary magic bytes `0x89 0x50 0x4E 0x47 0x0D 0x0A 0x1A 0x0A`.
  - JPEG: Verified binary magic bytes `0xFF 0xD8 0xFF`.
- **Integrity Checksums:** Incoming files are hashed using SHA-256 (`createHash("sha256")`).
- **Resource Limits:**
  - Maximum PDF size: `MAX_PDF_BYTES` (default 10 MiB).
  - Maximum image size: `MAX_IMAGE_BYTES` (default 7 MB).
  - Maximum page count: `MAX_PDF_PAGES` (default 50 pages).
  - Password-protected or corrupted PDFs are rejected immediately with safe error codes.

### 8. Sanitized Errors and Telemetry Logging
- **Log Isolation:** Structured AI extraction telemetry (`src/lib/ai/logger.ts`) logs only safe metadata:
  `{ event, runId, shipmentId, modelId, promptVersion, latencyMs, errorCode }`
  Raw prompts, base64 image strings, document contents, and API keys are strictly excluded.
- **Client Error Masking:** `apiError()` returns only fixed, typed messages written by our own code (upload, extraction, review, provider and `SafeRequestError` messages). Any other exception, including database and driver errors, returns HTTP 500 with a generic message and a short `errorId`. Provider, configuration and storage failures also carry an `errorId`. The server log line for that ID (`event: api_error`) holds only the ID, a safe error code and the error class, never the message or stack, so support can match a user report to a log entry without exposing content.

### 9. PII and Importer Contact Minimization
- **Export Scrubbing:** The canonical `demo-v1` export profile excludes phone numbers, personal mobile contacts, personal emails, and banking coordinates.
- **Customs-Only Fields:** Only authorized business fields (importer/exporter corporate names, document numbers, line items, weights, containers) and reviewer sign-off IDs are included in exported CSV files.

### 10 & 11. Client Retention & Complete Deletion Behavior
- **Cascade Deletion:** Database foreign keys are configured with `onDelete: Cascade`. Deleting a shipment or document atomically purges:
  - Document pages
  - Extraction runs
  - Extracted field records
  - Line items
  - Field correction histories
  - Cross-check runs and results
  - Cross-check resolutions
- **Physical Storage Deletion:** Implemented `deleteDocumentStorageObject()` and `deleteAuthorizedDocument()` (`DELETE /api/documents/[id]`), which removes the physical file from private Supabase Storage and cascades removal in PostgreSQL.
- **Approval Invalidation on Deletion:** Deleting a document from an approved shipment immediately invalidates the approval, bumps the revision, reverts status to `NEEDS_REVIEW`, and writes an immutable `DOCUMENT_DELETED` audit event.

### 12. Minimum Audit Metadata Policy
- **Audit Table Constraints:** `AuditEvent` records immutable operational logs containing:
  - `actorId` (User UUID)
  - `action` (e.g. `FIELD_CORRECTED`, `SHIPMENT_SUBMITTED`, `DOCUMENT_DELETED`)
  - `entityType` and `entityId`
  - Minimal JSON metadata (field key, previous value, new value, reason)
- Document content payloads and cryptographic keys are never stored in audit metadata.

### 13. Regional Compliance & Privacy Boundaries
- **Hosting Boundary:** The demo database and storage are hosted on Supabase in `ap-southeast-1` (Singapore), confirmed in the Supabase dashboard. This is not the preferred Mumbai (`ap-south-1`) region and not an India-only location. Moving to Mumbai requires a new project and a data migration before any real data is used.
- **AI Processing Boundary:** Groq (`qwen/qwen3.8-27b`) and OpenRouter process inference requests globally across their distributed cloud infrastructure (US Multi-Region).
- **Honest Compliance Statement:** CargoVerity makes **no blanket claims** of exclusive India-only data localization or DPDP compliance for third-party AI processing. All documentation clearly states that real customs documents and personal data must remain out of scope until dedicated regional enterprise agreements are established.
